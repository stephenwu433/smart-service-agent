# A1289 验收案例 1.0

来源：2 号验收案例文档。用于自动化测试用例对照。

## 主故事

### MS01 接错 C2，改接 C1 后恢复

- **用户情况**：我的 A1289 充不进去，线插在第二个 Type-C 口，屏幕一直没显示。
- **前置条件**：无鼓包、冒烟、异味、进液、异常发热；用户当前连接 C2。
- **预期路径**：R01 -> R02 -> R03 -> 指导改接 C1 -> 恢复稳定输入。
- **预期输出**：告知用户 A1289 应通过 C1 自充，本次问题由输入接口使用错误导致；改接 C1
  后已经恢复，流程结束。
- **不能出现的错误**：不能说 C2 支持输入；不能要求更换充电器或线材；不能转人工；不能判断
  产品本体故障；不能讨论充电速度。

### MS02 更换充电器无效，更换线材后恢复

- **用户情况**：A1289 接 C1，插座正常，我有备用充电器和 USB-C to USB-C 线。随后反馈：
  只换充电器还是不行，保持备用充电器再换线以后可以充了。
- **前置条件**：无安全风险；接口和插座问题已排除；替换充电器、替换线材均可使用。
- **预期路径**：R01 -> R02 -> R03 -> R04 -> X 选择两者都有 -> R05 只换充电器未恢复 ->
  R06 保持替换充电器、只换线材 -> 恢复。
- **预期输出**：初步判断原线材异常；记录充电器测试未恢复、线材测试恢复；流程结束。
- **不能出现的错误**：不能把原因归为原充电器；不能要求换回原充电器再测线材；不能同时更换
  两个变量；不能转人工。

### MS03 两项交叉测试均未恢复

- **用户情况**：A1289 接 C1，换插座没用。我先保持原线换了正常充电器，还是 0W；然后保持
  这个充电器换了正常 C 口线，仍然 0W。
- **前置条件**：无安全风险；接口、插座、充电器和线材均已按单变量原则测试。
- **预期路径**：R01 -> R02 -> R03 -> R04 -> X -> R05 未恢复 -> R06 未恢复 -> R07。
- **预期输出**：说明常见外部原因的交叉测试均未解决问题，初步判断为疑似 A1289 本体或 C1
  输入异常；收集连接、C1 接口、屏幕状态及配件信息，生成工单并转人工或售后。
- **不能出现的错误**：不能确认主板、电池或 C1 已经损坏；不能承诺换新或退款；不能再次要求
  重复 R05、R06；不能漏记两次测试结果。

## 正常边界

### NB01 充电宝无法给手机供电

- **用户情况**：A1289 自己可以正常充电，但是接上手机后手机不充电。
- **前置条件**：A1289 自身可以正常充电，异常发生在对外供电方向。
- **预期路径**：R01 识别为对外供电问题 -> 退出本流程。
- **预期输出**：说明当前问题是充电宝无法给外部设备供电，不属于充电宝自身充不进去，转
  对外供电流程。
- **不能出现的错误**：不能指导用户通过 C1 给充电宝自充；不能进入插座和自充配件测试；不能
  混淆输入与输出问题。

### NB02 产品型号不是 A1289

- **用户情况**：我的 A1259 充不进去，插着 1h 还是没电。
- **前置条件**：用户明确提供的型号为 A1259。
- **预期路径**：R01 识别非 A1289 -> 退出本流程。
- **预期输出**：告知用户本流程仅适用于 A1289，需要查询 A1259 对应的接口和排障规则。
- **不能出现的错误**：不能套用 A1289 的 C1 输入规则；不能声称 A1259 接口能力与 A1289
  相同；不能继续执行 R02 至 R07。

## 风险语言变体

### RV01 异味的间接表达

- **用户情况**：A1289 充不进去，而且一插电就有点像塑料烤焦的味道。
- **前置条件**：用户未直接使用"异味"一词，但描述了疑似烧焦气味。
- **预期路径**：R01 判断为 A1289 充不进去 -> R02 识别"塑料烤焦味"为异味风险 -> 停止
  普通排障。
- **预期输出**：要求立即停止使用和充电，不再执行接口、插座或配件测试，转人工或售后。
- **不能出现的错误**：不能把异味当作普通兼容性问题；不能继续通电测试；不能淡化为新产品
  气味。

### RV02 进液与异常发热的组合表达

- **用户情况**：昨天饮料好像洒到接口里了，今天一接电就烫得拿不住，现在也充不进去。
- **前置条件**：用户同时表达进液和异常发热风险。
- **预期路径**：R01 判断为充不进去 -> R02 同时识别进液和异常发热 -> 立即停止。
- **预期输出**：要求停止使用和充电，不再进行任何通电测试；记录进液、异常发热两项风险并
  转人工或售后。
- **不能出现的错误**：不能建议晾干后重新测试；不能让用户用吹风机、金属物或纸巾深入清理
  接口；不能遗漏任一风险标签。

## 模型异常

### MA01 用户信息前后矛盾

- **用户情况**：我确定接的是 C1，不对，可能是 C2；屏幕一会儿有显示，一会儿又说一直是
  0W。你直接判断哪里坏了吧。
- **前置条件**：端口信息和异常表现均存在互相矛盾的描述。
- **预期路径**：R01 识别关键事实冲突 -> 追问实际端口及屏幕状态 -> 信息澄清后重新执行 R01。
- **预期输出**：说明当前无法依据矛盾信息判断，请用户确认实际接口，并选择持续 0W、稳定
  输入、输入反复中断中的真实表现。
- **不能出现的错误**：不能擅自选择 C1 或 C2；不能把反复中断和持续 0W 视为同一事实；不能
  直接判断充电器、线材或产品本体损坏。

### MA02 IntentProvider 超时或非法 Schema

- **场景**：外部 intent provider 超时或返回非法 Schema。
- **预期**：安全降级，不绕过风险规则。
- **实现**：现有 `FallbackIntentProvider` 已覆盖；P0 测试新增 A1289 风险场景下的
  provider 超时用例（见 `tests/test_a1289_workflow.py` 中
  `test_ma02_provider_timeout_during_risk_still_blocks`）。

## 新增案例（本轮整理）

### CR01 C1 后更正为 C2

- **用户情况**：我之前说错了，我接的是 C2，不是 C1。
- **预期**：明确更正直接生效，局部撤回依赖 C1 的 Attempt，继续给出改接 C1 的指引。
- **实现**：`_detect_fact_correction` 识别明确新值后直接调用 `_apply_correction`；只有“可能是 C2”
  等模糊说法才返回 `state=ASK`。

### FB01 没有替代配件，无法执行

- **用户情况**：没有其他充电器或线材。
- **预期**：记录未测试并转人工；不把"没有配件"当作已排除该配件。
- **实现**：Sheet2 `none` 路径 -> HANDOFF；`_detect_accessories` 返回 `none`。

### FB02 部分改善或暂无法判断

- **用户情况**：好一点了，但还是不稳定 / 不确定是否算恢复。
- **预期**：不误结案、不误跳步。
- **实现**：`_looks_resolved` 与 `_is_stable_confirmation` 分开判定；`resolved_check` 阶段
  用户回"稳定"才结案。
