# 3 号开发交接总结

来源：2 号在开发开始前交给 3 号的正式交接文档。本文件把原始内容整理成 markdown，
方便与代码一起版本管理和 review。

## 一 先看结论

现有仓库可以直接作为 3 号的开发底座，但不能直接当作已经满足本次产品需求的成品。如果只完成
本文定义的 P0，3 天可以做出可演示、可测试的最小闭环；真实 LLM、完整 RAG、生产鉴权和多型号
扩展必须后置。

| 产品范围 | Anker 737 Power Bank PowerCore 24K A1289 自身无法充电 |

## 二 三天是否能完成

**判断可以完成最小闭环。** 前提是 3 号直接复用现有 FastAPI、数据模型、Repository、
Attempt、Ticket 和测试骨架，只补本次 A1289 场景真正缺少的状态与行为。

| 范围 | 三天结论 | 说明 |
|---|---|---|
| P0 必须 | 可完成 | A1289 单场景、风险锁、单步排障、反馈状态、事实更正与局部回退、人工交接、自动测试 |
| P1 有余力再做 | 可能完成一部分 | 规则知识配置化、工作台展示改进、语言变体 |
| P2 本轮不做 | 三天不现实 | 真实 LLM 与 RAG 效果优化、图片或视频理解、订单售后系统、登录 RBAC、多型号、多客服并发 |

### 三天完成的判断标准

- 三个结局都能从 API 或 Demo 页面重复跑通：正常解决 / 未解决升级 / 风险中断。
- 用户更正关键事实后，系统保留历史，只撤回依赖旧事实的步骤，再给出新步骤。
- 任意一轮出现冒烟、异味、鼓包、进液或异常发热后，风险锁跨轮保持。
- 固定验收案例自动化通过，且旧测试没有被削弱或删除。
- 代码、测试、API 文档和 CHANGELOG 一致。

### 三天明确不承诺

- 不承诺模型已经达到生产准确率。可以使用确定性规则或 mock provider 证明业务闭环。
- 不承诺已经接入真实订单、售后、文件存储、图片识别或企业账号系统。
- 不承诺已经支持其他型号或所有充电故障。

## 三 2 号材料统一总结

本节合并四份材料（产品知识、规则表、主流程图、验收案例）。它们是开发输入，不是可直接
执行的代码指令。

### 产品与场景

| 项目 | 统一内容 | 开发使用方式 |
|---|---|---|
| 产品 | Anker 737 Power Bank PowerCore 24K 型号 A1289 | 本轮只接受 A1289 进入主排障流程 |
| 问题 | 给充电宝自身充电时，无法建立或维持稳定输入 | 必须和对外给手机充电的问题分开 |
| 接口 | C1 支持输入和输出；C2 与 USB-A 仅输出 | 自充必须使用 C1 |
| 随附线 | 60cm USB-C to USB-C | 可作为知识信息，不能据此假设用户当前一定使用该线 |
| 观察 | 是否建立并维持稳定输入、屏幕或输入功率表现 | 每一步都必须记录用户观察，不能只记录系统建议 |
| 证据边界 | 产品页可支持型号、接口、功率等事实 | 没有来源或仍待核实的字段不得自动回答 |

### 全局规则

- 任何一轮出现安全风险，都立即停止普通排障。
- 用户无法执行某一步时，不能假装该项已经排除。
- 每次只改变一个条件；每个建议必须包含动作、观察标准、结果和下一步。

## 四 统一后的反馈规则

| 用户反馈 | 记录状态 | 系统下一步 | 禁止行为 |
|---|---|---|---|
| 尚未执行 | `proposed` | 保留当前步骤，询问是否准备执行 | 不能生成测试结果 |
| 已执行无改善 | `executed unchanged` | 保存观察，进入下一条有依据的规则 | 不能重复同一步 |
| 部分改善 | `executed improved` | 记录具体变化，继续确认是否稳定 | 不能直接结案 |
| 已经恢复 | `executed resolved` | 记录改变条件，询问用户是否确认解决 | 不能直接断言根因 |
| 无法执行 | `skipped unavailable` | 记录原因和未排除项，可转人工 | 不能强迫借配件或标记已排除 |
| 暂时无法判断 | `executed unknown` | 保留当前步骤，补问观察 | 不能自动进入下一步 |
| 明确事实更正 | `new fact revision` | 直接更新并撤回受影响步骤，保留无关事实 | 不能要求用户重复确认 |
| 模糊或矛盾信息 | `ASK` | 列出待确认事实并追问 | 不能擅自选一个事实 |
| 出现安全风险 | `BLOCK risk locked` | 停止通电排障，转人工或售后 | 不能因下一轮否认而自动解锁 |

### 事实更正与局部回退（核心差异化）

| 步骤 | 例子 | 系统应留下的记录 |
|---|---|---|
| 1 旧事实 | 用户说使用 C1 | `charging_port C1 revision 1` |
| 2 旧建议 | 系统给出依赖 C1 的交叉测试 | `attempt A depends_on charging_port revision 1` |
| 3 用户明确更正 | 用户说刚才看错，实际是 C2 | 直接写入 `charging_port C2 revision 2` |
| 4 局部撤回 | 依赖旧 C1 的 attempt A 失效 | `status withdrawn reason fact changed` |
| 5 继续 | 型号和安全信息仍保留，新增改接 C1 的步骤 | 新 attempt 使用 revision 2 |

> 实现说明：明确更正直接应用、撤回依赖旧值的 Attempt 并写 `case_revised` 审计；只有输入含
> “可能、好像、记不清”等不确定措辞，或同一消息内事实矛盾时，才返回 `state=ASK`。

## 五 争议点与本版处理

| 编号 | 争议 | 本版处理 | 状态 |
|---|---|---|---|
| D01 | 原流程先判断型号再查风险 | 风险检查改为全局优先，命中后设置跨轮风险锁 | 已冻结 |
| D02 | R07 要求继续寻找配件，Sheet2 允许直接转人工 | 没有、不愿或无法安全获得替代配件时，记录未测试并允许转人工 | 暂定默认 |
| D03 | 材料写非标准充电器和其他线材也可测试 | 只允许兼容、完好、符合安全标准的配件；无法确认则不做通电测试 | 已冻结 |
| D04 | 恢复后直接判断接口、插座或配件故障 | 只能记录"在改变条件后恢复"和可能原因；最终结案需用户确认 | 已冻结 |
| D05 | R08 把视频设为必要证据 | 视频改为可选；文字信息足够时也必须能建立工单 | 暂定默认 |
| D06 | 材料没有事实更正后的依赖撤回 | 加入事实版本、attempt 依赖和 withdraw 状态 | 已冻结 |
| D07 | 耐压 50V、质保 24、单位未核实 | 不得进入自动回复，等 2 号补官方来源和口径 | 禁止使用 |
| D08 | MA01 被称为模型异常 | 改为用户事实冲突，另加 provider 超时或非法输出测试 | 已冻结 |
| D09 | 用户下一轮说没风险是否自动解锁 | 不自动解锁；只有人工明确解除后才恢复普通流程 | 暂定默认 |
| D10 | 恢复是否直接等于解决 | 恢复后继续询问用户是否确认解决，未确认不关闭 | 已冻结 |

## 六 仓库能否直接交给 3 号

**结论：可以直接作为开发底座。** 仓库结构完整、模块边界清楚，已有 API、数据持久化抽象、
Attempt、Ticket、Eval 和测试。但本次产品核心行为尚未实现，3 号必须补齐，不能只改 prompt
或知识文本。

### 已核对的仓库状态（2026-09-21）

| 检查项 | 结果 | 判断 |
|---|---|---|
| 远程 main | commit 8ef8521 | 可作为统一基线 |
| 结构 | FastAPI / Pydantic / Repository / IntentProvider / KnowledgeProvider | 适合继续扩展，不需要重建 |
| 现有测试 | 34 条 pytest 全部通过 | 现有行为有基本回归保护 |
| Ruff lint | 通过 | 代码静态检查正常 |
| Ruff format | 2 个文件未通过 | 交付前需要格式化并复查 |
| 外部能力 | 真实 LLM / RAG / 文件 / 订单 / 鉴权未接 | 与三天 P0 无关，不应阻塞 |

### 可以直接复用

- `ConversationOrchestrator` 的状态路由框架。
- Case revision 的历史保留方式。
- Attempt 建议 / 执行 / 观察 / 结果分离的数据骨架。
- Ticket 与人工事件的幂等创建和结果记录。
- `IntentProvider` 和 `KnowledgeProvider` 的可替换接口及 fallback。
- `MongoRepository` 与 `MemoryRepository` 的持久化和测试替身。
- Eval 的数据指纹、HOLDOUT 门禁和安全失败阻断。

### 当前缺口（3 号必须补）

| 缺口 | 代码现状 | 需要补到什么程度 |
|---|---|---|
| 跨轮风险锁 | 主要按本轮消息判断，旧风险不会持续阻断 | `StoredConversation` 增加风险锁和解除来源；命中后后续轮仍 BLOCK |
| 进液风险 | 高风险词包含漏液，但未覆盖用户侧进液表达 | 加入进液等语言变体并测试 |
| 事实依赖 | Case 只有整份 revision，Attempt 没有 depends_on | Attempt 记录依赖的事实字段与版本 |
| 局部回退 | Case 更正不会自动影响旧 Attempt | 明确更正后，只把受影响 Attempt 标为 withdrawn |
| 步骤闭环 | GUIDE 只返回知识文本，Attempt 由独立 API 手工创建 | 主流程自动建立下一 Attempt，并根据反馈更新记录 |
| 反馈状态 | 只有 executed / skipped 和 improved / unchanged / worse / unknown | 覆盖无法执行、部分改善、已恢复、暂无法判断及下一步决策 |
| 人工交接包 | 主要包含客服动作，未完整汇总消费者 Attempt | 加入已执行、未执行、撤回和观察结果 |
| 知识内容 | 内置 3 条 demo 知识，不是 A1289 正式规则库 | 加入本次审核后的最小 A1289 知识和来源字段 |

## 七 3 号必须返回的接口行为

| 行为 | 最小输出字段 |
|---|---|
| 普通决策 | `state` `message` `evidence` `next_attempt` |
| 明确事实更正 | `old_fact` `new_fact` `new_revision` `withdrawn_attempt_ids` `preserved_fact_ids` `next_attempt` |
| 模糊事实更正 | `state=ASK` `confirmation_required=false` |
| 风险中断 | `state=BLOCK` `risk_lock=true` `reasons` `allowed_actions` |
| 人工升级 | `confirmed_facts` `attempts` `observations` `untested_items` `risks` `suggested_next_step` |

### 3 号不得自行决定

- 不得把耐压 50V 或质保 24 写入自动回复。
- 不得把恢复直接写成确定根因或硬件损坏。
- 不得把没有替代配件视为已经排除该配件。
- 不得让模型绕过风险锁、知识来源或 Schema 校验。
- 不得删除旧测试或降低断言来让新代码通过。

## 八 交接与验收方式

### 仓库交接

1. 仓库地址：https://github.com/stephenwu433/smart-service-agent
2. 先确认本地修改已推送，再把 3 号加入 Collaborator 或让 3 号 Fork 后提 Pull Request。
